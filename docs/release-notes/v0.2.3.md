# v0.2.3

## 中文

- 新增：
  - 会话详情改为一条平铺消息流（对齐 DSH 桌面端）：不再有 Turn 卡片、状态点与按轮折叠；推理与工具调用按「过程组」折叠，文件变更卡展示在流尾。
  - 端点自愈：连接成功后自动把 Mac 当前对外端点写回本机候选并持久化；同时用局域网 mDNS 发现 + 并行健康探测，网络变化后自动切到当前最快可用路径。
- 改进：
  - 行级懒加载：每行都是列表的直接子项（懒加载粒度从「整个 turn」降到「一行」），长会话滚动更稳，下拉加载的新消息不再被折叠遮住。
  - 连接更快：并行探测候选地址（同一 Wi-Fi 下 LAN 探测约 85ms），冷启动约 1.6s 连上；网络切换后自动重连约 0.4s（此前需等宿主端心跳超时，可能数十秒）。
  - 推送重入与分页的自动化覆盖扩展为 14 条真机 E2E（含只有中继、前后台恢复、网络切换场景）。
- 修复：
  - 修复「下拉两次仍停在同一个 turn」的误导：删除 turn UI 后，分页只按真实消息行推进，加载结果立即可见。
  - 修复网络环境变化后 App 长时间连不上 Mac、或反复重试极慢的问题。
  - 修复桌面端仍持有已失效 mux socket 时，新连接被判 409 冲突、手机只能等待超时的问题（静默超过 1.5s 的旧 mux 由新连接接管；活跃连接仍拒绝并发升级）。

## English

- New:
  - The session detail is a single flat message stream (matching the DSH desktop app): no turn cards, status dots or per-turn folding; reasoning and tool calls fold into a "process group", and the file-changes card sits at the end of the stream.
  - Endpoint self-healing: after every successful connect the app writes the Mac's current endpoints back into its persisted candidates, and combines LAN mDNS discovery with parallel health probes to pick the fastest reachable path after a network change.
- Improvements:
  - Row-level lazy loading: every row is a direct list child (granularity goes from one turn to one row), so long sessions scroll more smoothly and newly paged-in messages are never hidden behind a collapsed group.
  - Faster connections: candidates are probed in parallel (LAN probe ~85ms on the same Wi-Fi), cold start connects in about 1.6s, and a reconnect after a network switch completes in about 0.4s (previously it could wait tens of seconds for the host heartbeat timeout).
  - Automated coverage for push re-entry and paging grew to 14 on-device E2E cases (including relay-only, foreground/background and network-switch scenarios).
- Fixes:
  - Fixed the misleading "two pulls still stuck on the same turn" case: with the turn UI removed, paging advances by real message rows and the newly loaded content is visible immediately.
  - Fixed the app failing or taking very long to reconnect after the network environment changed.
  - Fixed new connections being rejected with a 409 conflict while the desktop still held a dead mux socket, which made the phone retry until a timeout (a mux silent for over 1.5s is now taken over by the new connection; active connections still reject concurrent upgrades).
