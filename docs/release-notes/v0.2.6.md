# v0.2.6

## 新增
- **全量历史自动加载**：进入会话详情即后台向前翻页直到最早一条，全程无按钮、无文案、无进度、无菊花；补齐完成后 `oldest=0 / holes=0`（本机 11.07MB / 815 行真实会话实测完成，8 页约 6–9 秒）。
- **消息列表 UIKit 反转底座**：`UITableView` 整体翻转 + cell 翻回，数据源新→旧排列，历史补齐 = 向数据源尾部追加，已有内容 content 坐标不变；行视图复用现有 SwiftUI（`UIHostingConfiguration`）。
- **布局期锚定兜底**：每次布局（屏幕提交前）按锚点行真实 frame 校正 contentOffset，不依赖行高估算。
- **贴底语义三件套**：贴底时新内容直接出现在底部；读历史时新消息先冻结、回到底部一次性出现；发送消息后强制回到底部（读历史时也能立刻看到自己刚发的消息）。
- **键盘/内联视口高度变化**时保持读历史的阅读位置，不再整体上跳再跳回。
- 首屏缓存升级（FirstPaintCache v5）、`FlowState` 增量渲染、`DetailMetrics` 首屏计时（tapMs/shellMs/contentMs/cacheMs/fillMs/fillPages/fillOldest）。

## 改进
- **滚动卡顿修复（真机手点定位）**：`JSONValue.decode` 内部是「JSON 重编码 → 目标类型解码」的双重转换，历史页/snapshot/大事件解码原本在 main actor（实测单页 111–466ms）→ 全部移到后台队列（历史页pageDecodeBG、stream frame 串行 FIFO 保持顺序）。
- 补齐期间不再逐批写窗口缓存（每批约 4MB JSON 编码 + 原子写，主线程 ~29ms）；缓存写入改后台队列 + 只保留最新一次，补齐完成/离开时统一写。
- 补齐批次逐批发布（不再延迟到补齐完成），补齐期间可正常滚动阅读。
- 真机测量基建修正：帧级探针只统计 `UITableView.visibleCells`（真正参与渲染的 cell），使用反转列表的正确坐标模型；新增 CA 提交后复核（`commitCheck`）区分「布局中间态」与「真实上屏」。

## 修复
- 修复补齐插入导致内容跳变（旧 SwiftUI 实现逐批插入单批可见位移 1871–4851pt，现为 0）。
- 修复读历史时发送消息看不到自己刚发消息的问题（发送后强制回底）。
- 修复键盘弹出时读历史内容整体跳动的问题。
- 修复冷缓存首开详情约 2 秒空白的问题（壳 18.7ms、首个内容 606.7ms，期间为骨架占位；热缓存首个内容 266.9–285.4ms）。
- 修复 **Release 构建编译失败**（DEBUG-only 帧级探针协议被生产代码无条件遵循）。
- 沿用前几轮修复：补齐瞬时错误有界重试、旧 schema 缓存静默丢弃、「正在刷新」横幅不再卡死。
