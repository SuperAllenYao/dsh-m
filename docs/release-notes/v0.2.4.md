# DSH-m v0.2.4

## 中文

DSH-m v0.2.4 是连接稳定性修复版本：针对真机上反复出现的「连接无响应，正在重连…」「点进会话要等十几秒」做了根因修复，并大幅降低详情页的网络流量。

- 新增：
  - 插件新增局域网端点自动刷新：Mac 换 Wi-Fi / 换网段后，mDNS 广播、`/health` 端点与配对载荷会跟随当前网络重建，不再把旧 IP 永久广播给手机。
  - 详情打开兜底策略：连接未就绪时先排队，连接一就绪自动补开；10 秒仍未就绪时显示可重试错误，不再无限转圈。
- 改进：
  - 详情页 `session/list` 轮询改用精简投影（lite）：单次响应从约 1.46MB（gzip 357KB）降到约 237KB（gzip 28KB），5G/中继下流量与带宽占用大幅下降。
  - 连接预算按真机实测重标定：跨网候选轮总预算 1.5s→5s、非末候选 2s→3s；`$events` ready 等待纳入候选预算（首次 ≤6s、重开 ≤2s）。
  - 首字节超时不再直接拆掉整条传输：先新建连接做 `/health` 存活校验，路径仍活则保留传输，只有确认失联才重连。
- 修复：
  - 修复 5G/中继慢抖动下 0.8s 首字节看门狗误杀整条传输、引发约 25 秒重连风暴与「连接无响应，正在重连…」横幅的问题。
  - 修复首装后首次冷启动详情加载可达 28 秒的问题（真机实测列表落地 28407.9ms→1056.5ms，下降 96.3%）。
  - 修复详情页每 8 秒全量拉取 1.5MB 会话列表的问题（60 秒详情停留内全量轮询 8 次→0 次）。
  - 修复冷启动未就绪时点进详情需等 3–4 秒 spinner 的问题（tap→首屏内容 4280ms→871ms）。
  - 修复 mDNS 端点自愈可能采纳 hostId 不匹配的 Mac 端点、以及在 `/health` 失败时仍使用未经校验中发现的中继端点的问题。
  - 修复单个候选地址凭据被拒就进入「需要重新配对」永久离线状态的问题（改为全部候选都被拒才需要重新配对）。
- 已知限制：
  - 插件的局域网端点自动刷新需重启 DSH 桌面端后生效；验证局域网直连需手机与 Mac 处于同一 Wi-Fi。
  - 中继建连偶发 3–4 秒（5G 抖动），但不再出现 28 秒级风暴，也不会因单次首字节超时触发整链重连。
  - 使用中继时详情轮询单次仍约 240KB，后续可继续精简投影字段。
  - 首次启动仍需允许「本地网络」权限才能使用局域网直连；拒绝后仍可经中继连接（延迟更高）。

## English

DSH-m v0.2.4 is a connection-stability release: it fixes the on-device symptoms of repeated "connection unresponsive, reconnecting…" banners and session details taking many seconds to load, and cuts detail-screen network traffic substantially.

- New:
  - The plugin now refreshes its LAN endpoints automatically: after the Mac joins another Wi-Fi network or subnet, the mDNS advertisement, `/health` endpoints and pairing payload are rebuilt for the current network instead of advertising stale IPs forever.
  - A deferred-open policy for session details: when the link is not ready the open is queued and resumed as soon as the link connects; if it is still down after 10 seconds the screen shows a retryable error instead of spinning forever.
- Improvements:
  - Detail-screen `session/list` polling uses the lite projection: a single response drops from about 1.46MB (357KB gzipped) to about 237KB (28KB gzipped), sharply reducing cellular/relay bandwidth.
  - Candidate budgets re-calibrated from on-device measurements: cross-network round budget 1.5s→5s, non-last candidate 2s→3s; the `$events` ready wait is now bounded by the candidate budget (≤6s first try, ≤2s on reopen).
  - A first-byte timeout no longer tears down the whole transport: a fresh `/health` probe verifies the path first and the transport is kept when it is still alive.
- Fixes:
  - Fixed the 0.8s first-byte watchdog killing an alive transport during a 5G/relay stall, which caused a ~25s reconnect storm and the "connection unresponsive, reconnecting…" banner.
  - Fixed the first cold start after install taking up to 28 seconds to load the session list (measured 28407.9ms→1056.5ms, a 96.3% drop).
  - Fixed the detail screen pulling the full 1.5MB session list every 8 seconds (full polls during a 60s detail dwell: 8→0).
  - Fixed tapping a session before the cold-start link was ready waiting 3–4 seconds on a spinner (tap→first content 4280ms→871ms).
  - Fixed mDNS endpoint self-healing adopting a Mac endpoint with a mismatched hostId, and using an unverified relay endpoint discovered from a failed `/health` probe.
  - Fixed a single rejected candidate credential flipping the app into a permanent "re-pair required" offline state (now requires every candidate to reject).
- Known limitations:
  - The plugin's LAN endpoint refresh takes effect after restarting the DSH desktop app; verifying direct LAN connections requires the phone and Mac on the same Wi-Fi.
  - Relay connections occasionally take 3–4 seconds (5G jitter), but the 28-second storm is gone and a single first-byte timeout no longer forces a full reconnect.
  - Over the relay a detail poll is still about 240KB; projection fields can be trimmed further later.
  - On first launch the app still needs the Local Network permission for direct LAN access; if denied it connects through the relay (higher latency).
