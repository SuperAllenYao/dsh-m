# DSH-m v0.2.7

## 中文

DSH-m v0.2.7 是「工作步骤内联 + 过程组四态 + 跨端一致性收尾」版本：把工作步骤从悬浮面板改为**内联在消息流里**，按「运行中 / 已结束 × 折叠 / 展开」提供四态；同时修掉三个真机报障的系统性根因（整页无法滑动、读历史点组头无反应、cell 内展开被旧行高裁剪）与文件变更取数的两个健壮性缺陷。

- 新增：
  - **过程组四态内联**：运行中默认「高度受限窗口」（上限整屏 1/3、clamp 280–360pt；步数少时按内容自适应，不留空白），底部对齐展示最新步骤；点组头右侧箭头（窗口/折叠态 ▶、全高/展开态 ▼，与 DSH 桌面端 TurnProcess 箭头一致，100ms 旋转）→ 全量内联，再点回窗口；本轮结束自动折叠成一行「N 步 · …」（组头不再出现「过程」二字），点该行 → 展开全部历史步骤，再点 → 收起。
  - **展开/收起交互**：被点击的组头在屏幕上**严格固定不动**——内容向下展开、自下而上收起，150ms ease-in-out 非线性动画；不使用任何自动滚动/上移。
  - **失败步骤回到步骤序列**：失败/待审批步骤按事件原始顺序内联在过程组内（不再单拎成独立卡片；折叠态不单独显示），与 DSH 桌面端展示顺序一致。
  - **跨端文件变更一致性**：卡片标题文件数改用 Host `total`（不再是客户端 `files.length`）；精确摘要未到时卡片/sheet 显示 loading 态，不拿近似值冒充；打开 sheet 时重新取数。
- 改进：
  - **R0 手势还给外层列表**：运行中窗口去掉嵌套 `ScrollView`，只渲染窗口容量内的最近 N 步（底部对齐），纵向 pan 不再被窗口吞掉 → 整页消息列表恢复上下滑动；看全部用「全高」。
  - **消息列表原生 SwiftUI 重写（最终方案）**：消息流从 UIKit 反转 UITableView 改为原生 `ScrollView + LazyVStack`，展开/收起完全由 SwiftUI 布局动画驱动，展开内容不再被旧行高裁剪、也不再有自撑高行高与隐式动画错配；长会话整页滚动门禁耗时从 ~205s 降到 26.6s。
  - **运行中窗口高度自适应**：窗口高度 = min(整屏 1/3, 整行吸附的内容高度)，步骤少时不再出现大片空白。
  - **通用折叠/展开锚点交互**：任何可展开行（过程组、思考块、中继卡、用户问题卡）点击后，**被点行在屏幕上位置严格不动**，展开内容把下方 UI 向下挤开、收起反向拉回，统一 150ms ease-in-out。
  - **R2 读历史冻结**：读历史（不在贴底区）时尾部新内容暂不插入（保持阅读位置），过程组模式/turn 相位等交互变更仍然立即生效；回到贴底时一次性补齐最新内容。
  - **R3 运行中组判定**：新增「本轮起点 seq」（`isNewest = 最后一个组 && firstSeq > currentTurnStartSeq`），刚发消息时上一轮组不再闪成运行中窗口。
- 修复：
  - 修复运行中固定窗口吞纵向手势导致**整页消息列表无法上下滑动**。
  - 修复读历史时点「过程 · N 步」**无反应**（交互被冻结门吞掉、后续 diff 丢失）。
  - 修复单独思考块点开后**看不到全文**（cell 内展开行高不失效 / 内容被裁剪）。
  - 修复思考块**点开后收起时行高不回收**、上下上下文内容不归位（原先只对「变高」触发重测）。
  - 修复运行中窗口在步骤较少时**上方大片空白**（窗口高度按内容自适应，上限 1/3 屏）。
  - 修复运行中组角标语义与桌面端相反：改为折叠/窗口态 ▶、全高/展开态 ▼。
  - 修复过程组组头多余文案「过程 · 」，改为直接显示「N 步 · …」。
  - 修复折叠/展开**整屏弹跳 / 内容闪动**（过程组、思考块、子代理卡、问题详情）：消息列表由 UIKit 反转 UITableView 重写为**原生 SwiftUI ScrollView + LazyVStack**，展开/收起交回 SwiftUI 布局动画（150ms ease-in-out + 裁剪），彻底移除此前「self-sizing 行高 + 隐式动画」错配导致的跳变；贴底跟随、读历史冻结尾部、历史补齐保持阅读位置、强制回底等行为在新列表中保持一致。
  - 修复会话详情页**滚动后被自动吸回固定位置**（冷启动也会）：逐帧锚点只对「用户主动点击的展开体」生效，首屏渲染/流式内容/历史补齐的行高变化改回无锚点重测。
  - 修复一轮结束收到**多条「DSH 回合完成」通知**：插件侧按 APNs push token 去重、配对成功及启动时清理历史重复设备记录，并给 turn-end/failure 加 `apns-collapse-id`（同一事件重复投递由 iOS 折叠成一条）。
  - 修复刚发消息时上一轮过程组闪成运行中窗口。
  - 修复文件变更卡片在 Host 已释放摘要（404）时**整卡消失**：链路插件把已经解压的 error body 配上 `content-encoding: gzip` 透传，客户端把 404 误判成可重试的传输错误并耗尽重试；现改为解压失败回退原始 body，正确进入 404 终态并走近似兜底。
  - 文件变更兜底聚合兼容 `message.meta`（部分恢复快照只保留该位置；真实会话仍以 `data.meta` 为准）。
  - 文件变更 fallback 列表行补齐可测性标识（E2E 可计数/定位）。
- 已知限制：
  - 运行中窗口**不提供窗口内手动滚动**（自动跟随最新步骤），看全部请点「全高」。
  - 窗口高度上限为整屏 1/3（clamp 280–360pt），步数少时按内容自适应。
  - 展开/收起时组头严格固定、**不做自动滚动**：步骤超出屏幕时需要手动滚动查看；当整段会话内容不足一屏（无滚动余量）时无法把组头钉住，展开仍会向上长（极端短会话限制）。
  - 本轮结束即自动折叠为一行（桌面端是等下次输入才收，移动端更主动）。
  - 历史会话的 Host 精确摘要已释放时，卡片显示「工具聚合」近似口径并标注来源，不是 Host 精确值。
  - 插件为 v0.2.7（本版插件有通知去重行为改动：推送按 token 去重、清理重复设备记录、`apns-collapse-id`）；桌面端需重启后加载新版本号并生效。
  - E2E 插桩（`DSHM_E2E=1` 等）会放大渲染瞬态，仅测试环境出现，生产构建零开销。

## English

DSH-m v0.2.7 is the "inline work steps + four-state process group + cross-end consistency" release: work steps move from a floating panel to **inline in the message stream**, with four states (running / finished × collapsed / expanded); it also fixes three systemic root causes reported on device (the page could not scroll, tapping a group header while reading history did nothing, and in-cell expansion was clipped by the stale row height) plus two robustness defects in file-change fetching.

- New:
  - **Four-state inline process group**: running turns default to a **height-capped window** (max 1/3 of the screen, clamped 280–360pt; shrinks to its content when there are few steps, so no blank area) that bottom-aligns the newest steps; tapping the header chevron (▶ in window/collapsed, ▼ in full/expanded, matching the DSH desktop TurnProcess arrow, 100ms rotation) switches to **full inline**, tapping again returns to the window; when the turn ends the group auto-collapses to a single "N 步 · …" row (the word "过程" is gone) — tap to expand all historical steps, tap again to collapse.
  - **Expand / collapse interaction**: the tapped group header is **pinned strictly in place on screen** — content unfolds downward and retracts upward, with a 150ms ease-in-out non-linear animation; no automatic scrolling or upward shifting is applied.
  - **Failed steps are back in the step sequence**: failed / pending-approval steps are rendered in their original event order inside the group (no longer split into a separate card; not shown when collapsed), matching the DSH desktop order.
  - **Cross-end file-change consistency**: the card title now uses the Host `total` (not the client-side `files.length`); while the exact summary is loading, card/sheet show a loading state instead of presenting the approximate aggregate as truth; opening the sheet re-arms a failed exact fetch.
- Improvements:
  - **R0: gestures returned to the outer list** — the running window no longer embeds a nested `ScrollView`; it renders only the newest N steps that fit the window (bottom-aligned), so vertical pans are no longer swallowed and whole-page scrolling is restored; use "full height" to see everything.
  - **Native SwiftUI message list (final approach)** — the message stream moved from the inverted UIKit UITableView to a native `ScrollView + LazyVStack`; expand/collapse is driven entirely by SwiftUI layout animation, so expanded content is no longer clipped by a stale row height and there is no self-sizing/implicit-animation mismatch; the long-session full-page scroll gate dropped from ~205s to 26.6s.
  - **Running window height adapts to content**: height = min(1/3 screen, whole-row-snapped content height); with few steps there is no more large blank area.
  - **Generic anchored expand/collapse**: for any expandable row (process group, reasoning block, relay card, user-question card), **the tapped row stays strictly in place on screen**; expanded content pushes the UI below it downward and collapsing pulls it back, uniformly with a 150ms ease-in-out animation.
  - **R2: frozen tail while reading history** — while reading history (not near the bottom), new tail content is not inserted (the reading position is kept), while interaction changes (process-group mode / turn phase) still apply immediately; the latest content is merged in one go when the user returns to the bottom.
  - **R3: running-group detection** — a new "current turn start seq" (`isNewest = last group && firstSeq > currentTurnStartSeq`) prevents the previous turn's group from flashing as running right after sending a message.
- Fixes:
  - Fixed the whole message list being **unscrollable** because the running window swallowed vertical pan gestures.
  - Fixed tapping "过程 · N 步" while reading history doing **nothing** (interaction swallowed by the freeze gate; subsequent diffs lost).
  - Fixed a standalone reasoning row not showing its **full text** after tapping (in-cell expansion clipped by the stale row height).
  - Fixed **collapsing an expanded reasoning row** not reclaiming its row height, leaving the surrounding content out of place (previously only growth triggered a re-measure).
  - Fixed the large **blank area above the running window** when the turn had few steps (window height now adapts to content, capped at 1/3 screen).
  - Fixed the running-group toggle icon semantics being opposite to the desktop: now ▶ for window/collapsed and ▼ for full/expanded.
  - Removed the redundant "过程 · " prefix from the group header (now "N 步 · …").
  - Fixed the **whole-screen bounce / content flash on expand and collapse** (process group, reasoning, relay, user-question): the message list was rewritten from the inverted UIKit table view to a **native SwiftUI ScrollView + LazyVStack**, so expand/collapse is driven by SwiftUI layout animation (150ms ease-in-out with clipping) and the self-sizing/implicit-animation mismatch is gone; bottom following, frozen tail while reading history, history-prepend position keeping and force-to-bottom all behave as before.
  - Fixed the session detail page **snapping back to a fixed offset after scrolling** (also on cold start): per-frame anchoring now only applies to rows the user explicitly tapped; first-paint / streaming / history-backfill height changes go back to the non-anchored re-measure path.
  - Fixed receiving **multiple "DSH 回合完成" notifications for one turn**: the plugin dedupes push targets by APNs token, prunes duplicate device records on pairing and at startup, and sets `apns-collapse-id` for turn-end/failure pushes (iOS collapses duplicate deliveries into one).
  - Fixed the previous turn's process group flashing as a running window right after sending a message.
  - Fixed the file-change card **disappearing entirely** when the Host released the summary (404): the link plugin passes an already-inflated error body together with `content-encoding: gzip`, so the client misclassified the 404 as a retryable transport error and exhausted its retry budget; the client now falls back to the raw body when inflation fails, reaches the 404 terminal state and shows the approximate fallback.
  - The file-change fallback aggregate now also reads `message.meta` (some restored snapshots only keep it there; real sessions still use `data.meta`).
  - Added accessibility identifiers to fallback file-change rows for E2E count/locate.
- Known limitations:
  - The running window offers **no in-window manual scrolling** (it follows the newest steps); use "full height" to see everything.
  - Window height is capped at 1/3 of the screen (clamped 280–360pt) and shrinks to its content when there are few steps.
  - Expand/collapse pins the header strictly and **never auto-scrolls**: steps beyond the screen require manual scrolling; when the whole conversation is shorter than one screen (no scroll room) the header cannot be pinned and expansion still grows upward (extremely short sessions only).
  - A finished turn auto-collapses immediately (desktop collapses when the next input arrives; mobile is more eager).
  - When the Host no longer holds the exact summary for a historical turn, the card shows the "tool aggregate" approximation with its provenance instead of the Host-exact numbers.
  - Plugin is v0.2.7 (this release changes notification behaviour: push fan-out deduped by token, duplicate device records pruned, `apns-collapse-id` added); restart the desktop app to load and activate it.
  - E2E instrumentation (`DSHM_E2E=1` etc.) amplifies rendering transients and only exists in test builds; production builds have zero overhead.
